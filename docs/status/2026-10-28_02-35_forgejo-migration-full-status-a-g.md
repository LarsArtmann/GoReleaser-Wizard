## e) WHAT WE SHOULD IMPROVE

1. **Read-then-write discipline for tests**: derive test expectations from the actual API surface (enum names, constructor side effects) before drafting.
2. **Scratch-repo-first smoke testing**: prove a new CLI path in a throwaway module before running it against a real repo (dnsblockd deserved better than being the debug target).
3. **Fight the daemon where the ritual works**: in GoReleaser-Wizard, use explicit `treefmt <files> && git add <files> && git commit --no-verify` as ONE command for every meaningful commit.
4. **writeShellApplication idiom checklist**: pipefail-safe command substitutions (`|| true`), no brace-y sed patterns, jq assertions over grep assertions, `${var%%pattern}` over sed for suffix stripping — memorize as a personal pre-commit review list.
5. **Fixture-first for API-shaped scripts**: write the stub key table BEFORE the script, so the API shape (paths, payload fields, status codes) is pinned twice.
6. **Golden update + full suite as one gate**: `-update-golden` should run the suite again after regenerating (the flag-leak failure mode).
7. **Better CLI output hygiene**: final success tips should be provider-aware (forgejo runs should point at `.forgejo/workflows`, not `.github/workflows/release.yml`).
